# БИЗНЕС-ЛОГИКА И СТАНДАРТЫ ПРОЕКТА CONTRACTORSYSTEM

Этот файл заменяет собой устаревшие своды правил (`business-logic-rules.md`, `project-rules.md`). Все правила здесь **обязательны к выполнению**.

## 1. Языковые стандарты
- **Агенты ИИ общаются ИСКЛЮЧИТЕЛЬНО на русском языке.** Любые отчеты, логи, комментарии к коду и развернутые планы должны быть написаны на русском.
- **Терминология:** Допускается использование английских и ивритских терминов (например, *BOQ*, *V.O.*, *כתב כמויות*) **СТРОГО в скобках** рядом с русским значением.
- **Интерфейс (UI):** Весь пользовательский интерфейс, тексты кнопок, оповещения, ошибки и названия колонок экспорта (CSV, PDF) должны быть **исключительно на иврите (עברית)**.

## 2. Финансовые стандарты (КРИТИЧЕСКИ ВАЖНО)
- **Валюта:** Израильский шекель (₪ / ILS / NIS).
- **База данных:** Все суммы в таблице `pricing_ledger` **ОБЯЗАНЫ** храниться **БЕЗ НДС** (לפני מע"מ).
- **НДС (VAT / מע"מ):** Ставка НДС равна **18% (0.18)**. Это правило имеет приоритет над любыми дефолтными значениями в старых миграциях Supabase (где могло быть 17%). НДС добавляется и отображается только на уровне UI (Client-side) или при серверном экспорте (PDF/CSV).

## 3. PRD-First Development
Запрещено писать код или принимать архитектурные решения без предварительного анализа требований Product Requirements Document, расположенных в `docs/specs/`:
- `PRD_Architecture_Specs.md`
- `PRD_Comparison_Engine.md`
- `PRD_Contract_Documents.md`
- `PRD_Database_Schema.md`
- `PRD_Design_System.md`
- `PRD_Main_Page.md`
- `PRD_Pricing_and_VO.md`
- `PRD_Project_Dashboard.md`

## 4. Архитектурный стиль (Clean Architecture)
- **Фронтенд:** Next.js 16 (App Router), React 19, TypeScript, Tailwind CSS v4.
- **Бэкенд:** Вычислительные задачи (парсинг BOQ, OCR) выносятся в отдельный Express worker (`src/worker.ts`), чтобы не блокировать потоки Next.js.
- **БД и Авторизация:** Supabase (пользователи — это подрядчики, у каждого профиля есть доступ только к своим `projects`).
- **Изоляция логики:** Визуальные компоненты (`src/components/features/`) не должны содержать сложной бизнес-логики. Обработка данных происходит через API стейт-менеджмент.

## 5. Защита от регрессий (TDD)
Любой код, связанный со сравнением контрактов, подсчетом сумм и генерацией PDF, должен быть покрыт тестами или строгими TypeScript типами.
