# STATUS DOCUMENT (CONTINUITY)

Актуально для Codex-перехода ContractorSystem.

## Текущий статус

- Проект продолжает жить в Codex без переписывания архитектуры с нуля.
- Gemini-стандарт обновлен: основной бренд и API-модель проекта используют `gemini-3.5-flash`.
- По официальной документации Google AI от 19 мая 2026 `gemini-3.5-flash` является stable model code и поддерживает text/image/video/audio/PDF input, structured outputs и caching.
- НДС в логике проекта закреплен как 18%; суммы в Pricing Ledger считаются без НДС, НДС показывается отдельно.
- Повторное обновление страницы не должно заново тратить Gemini/OCR, если файл и извлеченный текст не изменились.
- Contradiction Radar и Pricing Ledger должны показывать evidence/verification markers и не делать уверенные выводы без источников.

## Закрытые блокеры

- Старый риск 17% НДС устранен миграцией и runtime-логикой.
- Фиктивная уверенность документов `98.4%` удалена.
- Статус `DONE` заменен на поддерживаемую модель статусов, при этом сохранена совместимость со старыми записями.
- `/login` переведен в dynamic mode, production build проходит.
- Перенос в Pricing больше не создает нулевую финансовую строку без явной оценки.
- Evidence теперь переносится из Radar в Pricing и блокирует официальное письмо, если доказательства не подтверждены.
- Сканер документов очищен от поврежденной кодировки и получил contractor-first правила для contradictions, site events, missing data и Zero Match.
- Кеш сканирования теперь помнит даже результат “ничего не найдено”, чтобы не тратить Gemini повторно.

## Осторожно

- Старые contradictions до нового контролируемого скана остаются legacy-результатами.
- В базе есть существующая строка ledger без описания и с большой суммой; не удалять без отдельного подтверждения владельца.
- Untracked `skills` существовал до текущих правок и не относится к Codex-изменениям.
- `npm run lint` все еще показывает старый общий lint-долг проекта; сборка и TypeScript проходят.

## Следующий рекомендуемый этап

1. Запустить контролируемый scan только на реальном проекте с документами, когда владелец подтвердит расход Gemini.
2. Проверить новые findings: evidence status, source quotes, contractor action, Zero Match и финансовый смысл.
3. Отдельно решить, что делать с подозрительной ledger-строкой.
