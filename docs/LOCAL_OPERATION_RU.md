# Работа с установленной ContractorSystem

Программа работает на этом компьютере по адресу http://127.0.0.1:3002/. После перезапуска Windows её можно запустить файлом Start-ContractorSystem.cmd в папке проекта. Собирать код или устанавливать зависимости для обычной работы не требуется.

Запуск повторно использует уже работающую версию. Программа и её собственные зависимости сохранены в C:/Users/97254/AppData/Local/ContractorSystem; временная папка разработки для запуска не нужна. Текущий выпуск указан в current.json, журнал запуска — в logs. Адрес 127.0.0.1 относится именно к этому компьютеру; внешний доступ этим выпуском не включён.

## Повседневная работа

- Рабочие действия выполняются кнопками программы. В разделе писем обычная корреспонденция отделена от финансового требования. Стиль выбирается в форме, готовый текст можно редактировать.
- Сохранение создаёт черновик. Скачивание и печать доступны отдельно. Отметку отправки ставят только после настоящей отправки вне программы; сама программа письма адресатам не отправляет.
- Консультант сохраняет беседу в системе. Ссылки и ограничения раскрываются отдельно от основного ответа. Новый вопрос продолжает выбранную беседу.
- У документа различаются сохранённый файл, полнота чтения, предложение помощника и ручное подтверждение. Кнопка завершения чтения источника доступна независимо от генерации. Непрочитанный материал не становится подтверждённым указанием.
- Рабочие письмо, консультант и разбор документа используют уже согласованный служебный контур Codex. Принятые локальные радар и расценки сохранены. Выбор модели текущего чата разработки не меняется.

## Обновление и возврат — для сопровождения

У каждого сохранённого выпуска есть release.json с исходными файлами, сборкой, контрольными суммами, версией Node и зависимостей. local-system-package.mjs создаёт новый каталог; существующий выпуск не перезаписывает. Сначала local-system-launch.mjs verify запускает пакет на отдельном разрешённом порту и останавливает только собственный процесс.

Установка на3002 проверяет новый и прежний пакет до переключения. Остановка сверяет сборку, PID, команду, исполняемый файл и время создания процесса. При отказе нового запуска автоматически восстанавливается предыдущая программа. Занятый посторонним приложением порт не освобождается принудительно.

В AppData сохранён launcher.mjs. Его команды: start, status, install --release ИД, rollback, stop. Используется Node, указанный в release.json; профиль рабочего помощника не переопределяется. Возврат касается программного выпуска. Новые письма, документы и финансовые данные старой копией базы не заменяются.

## Резервные копии и восстановление

local-system-backup.mjs сохраняет все используемые публичные бизнес-таблицы и реальные байты Storage, вместе со схемой и правами из ops/backup-schema.json. Во время копирования бизнес-задания должны быть завершены: таблицы повторно сверяются перед окончанием. Завершённая копия не перезаписывается. Параметр --reuse использует только проверенные байты прежней копии с теми же ключом, версией и контрольной суммой.

local-system-restore.mjs восстанавливает копию в новый изолированный локальный контейнер PostgreSQL без сети, опубликованных портов и подключения пользовательских каталогов. Проверяются строки, связи, права владельца и постороннего пользователя, права функций и все файлы. После проверки контейнер останавливается. Рабочая удалённая база при этом не меняется. Исходные ключи файлов сохраняются в карте восстановления; это проверка восстановления бизнес-данных, а не автоматическое развёртывание всего облачного Supabase.

Пароли, ключи API и учётные данные Auth в бизнес-копию не входят. Они остаются в прежних закрытых настройках и учётной записи. Копии содержат документы проекта и хранятся только локально в AppData; в GitHub они не публикуются.

## При продолжении разработки

Сначала читать AGENTS.md, HANDOFF_CURRENT_RU.md и текущую матрицу R01–R12. Действующая программа и исходная папка Кирьят-Гата не являются временными тестовыми каталогами. Старые пользовательские изменения, историю и применённые миграции не сбрасывать. Номер фактически применённой миграции корреспонденции:20261031083727_project_correspondence; файл исходного SQL:20261031120000_project_correspondence.sql. Повторно применять его к нынешней базе не требуется.

Технические проверки не заменяют приёмку реального результата. Открытые условия чтения источников и интерфейса указаны в R01_R12_DELIVERY_RU.md; их нельзя отмечать завершёнными только по успешной сборке.
