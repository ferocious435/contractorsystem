# Работа с установленной ContractorSystem

Программа работает на этом компьютере по адресу http://127.0.0.1:3002/. После перезапуска Windows её можно запустить файлом Start-ContractorSystem.cmd в папке проекта. Собирать код или устанавливать зависимости для обычной работы не требуется.

Запуск повторно использует уже работающую версию. Программа и её собственные зависимости сохранены в C:/Users/97254/AppData/Local/ContractorSystem; временная папка разработки для запуска не нужна. Текущий выпуск указан в current.json, журнал запуска — в logs. Адрес 127.0.0.1 относится именно к этому компьютеру; внешний доступ этим выпуском не включён.

## Повседневная работа

- Рабочие действия выполняются кнопками программы. В разделе писем обычная корреспонденция отделена от финансового требования. Стиль выбирается в форме, готовый текст можно редактировать.
- Сохранение создаёт черновик. Скачивание и печать доступны отдельно. Отметку отправки ставят только после настоящей отправки вне программы; сама программа письма адресатам не отправляет.
- Консультант сохраняет беседу в системе. Ссылки и ограничения раскрываются отдельно от основного ответа. Новый вопрос продолжает выбранную беседу.
- У документа различаются сохранённый файл, полнота чтения, предложение помощника и ручное подтверждение. Кнопка завершения чтения источника доступна независимо от генерации. Непрочитанный материал не становится подтверждённым указанием.
- Рабочие письмо, консультант и разбор документа используют уже согласованный служебный контур Codex. Принятые локальные радар и расценки сохранены. Выбор модели текущего чата разработки не меняется.

## Обновление и возврат — для сопровождения

У каждого сохранённого выпуска есть release.json с исходными файлами, сборкой, контрольными суммами, версией Node и зависимостей. local-system-package.mjs создаёт новый каталог; существующий выпуск не перезаписывает. Сначала local-system-launch.mjs verify запускает пакет на отдельном разрешённом порту и останавливает только собственный процесс.

Установка на3002 проверяет новый и прежний пакет до переключения. Остановка сверяет сборку, PID, команду, исполняемый файл и время создания процесса. При отказе нового запуска автоматически восстанавливается предыдущая программа. Занятый посторонним приложением порт не освобождается принудительно.

В AppData сохранён launcher.mjs. Его команды: start, status, install --release ИД, rollback, stop. Используется Node, указанный в release.json; профиль рабочего помощника не переопределяется. Возврат касается программного выпуска. Новые письма, документы и финансовые данные старой копией базы не заменяются.

## Резервные копии и восстановление

Управляемое обслуживание сохраняет завершённые копии в локальном HOME/backups, проверяет все объявленные таблицы, перечень Storage, размеры и байты файлов, затем перечитывает ZIP вместе с его контрольным описанием. Обычная проверка копии выполняется один раз за местный календарный день Asia/Jerusalem; перед техническим изменением данных или схемы используется обязательная предварительная проверка. Неудачная предварительная копия блокирует зависимую операцию. Обычное редактирование полей в программе не запускает полный экспорт перед каждым сохранением.

Параметр --reuse сохранён для совместимости. Он больше не разрешает брать прежние байты Storage вместо нового чтения: при наступившей проверке содержимое скачивается заново. Если полная новая сверка совпала, сохраняется небольшая запись о проверке прежней точки. Таблицы и Storage сверяются повторно, но общего транзакционного снимка базы и Storage на один момент этот механизм не создаёт. Схема берётся из проверенных метаданных выпуска либо явно заданного файла; перед настоящей копией сопровождение отдельно сверяет её с текущей базой.

В установленном комплекте доступны команды launcher.mjs maintenance backup, backup-status и restore. Восстановитель принимает --backup с завершённой папкой формата v2 либо самостоятельным ZIP формата backup-v2+zip-v1 и его неизменённым соседним .manifest.json. Старые и неполные копии защищены от ротации; поддержка старого формата v1 этим восстановителем не подтверждается. Повреждённые или небезопасные входные файлы отклоняются до обращения к Docker.

Испытание восстанавливает схему, бизнес-строки, предусмотренные права и исходные байты Storage в новый собственный PostgreSQL. Используется только явно закреплённый локальный адрес Docker в Windows; удалённый адрес и неизвестный контекст отклоняются до передачи данных. Настройки Docker не меняются. Берётся только уже установленный образ postgres:17.6: без загрузки образов, открытия Docker UI, сети, опубликованных портов и подключения папок компьютера. Сохраняются проверки владельца и постороннего пользователя, прав функций и операции хода чтения, если она требуется схемой. Результат привязан к точным ID, содержимому, схеме, формату и контрольным суммам ZIP вместе с его боковым описанием; произвольный JSON со словом passed не принимается как доказательство.

Без --destination испытательные файлы сохраняются только в собственных каталогах maintenance-state/restore-scratch. Уборка сверяет исходно известный перечень созданных файлов и папок; появление постороннего обычного файла останавливает удаление. После проверки удаляются лишь эти проверенные каталоги и собственный контейнер с его новыми анонимными томами. Компактное доказательство остаётся в maintenance-state/restore-evidence; прежние доказательства не перезаписываются. Во время проверки архивная точка закреплена от ротации. Неизвестный или подменённый объект не удаляется; незавершённая уборка не получает успешного результата. После аварийного завершения процесса могут остаться защищённые временные каталоги и закрепление: автоматически чужим запуском они не снимаются.

Явный --destination сохраняет прежнее назначение: указывает новый отдельный каталог для проверенных копий файлов Storage, карты storage-paths-and-hashes.json и recovery-proof.json. Этот выбранный результат остаётся у оператора; собственные временные каталоги и контейнер всё равно убираются. Существующий каталог не перезаписывается, исходная копия не изменяется. При прерывании явный выход может остаться неполным; успешное доказательство для такой попытки не записывается. SQL dump этот параметр не создаёт.

Повторная проверка восстановления запускается после успешного обычного start, install или rollback, в том числе при повторном запуске уже работающей программы и неизменившейся ежедневной копии. Отдельного планировщика нет. Проверка нужна при изменении схемы/формата либо по истечении 30 суток от успешного доказательства. Используется согласованная календарная замена 30 активных дней; точный счёт активных дат не ведётся, поэтому перерыв в работе тоже приближает проверку. Та же граница — меньше 30 полных суток — действует для допуска ротации. Если движок или локальный образ недоступен, UI не открывается, прежнее доказательство сохраняется, новая попытка получает статус unavailable. Просроченное, повреждённое или неподходящее доказательство ротацию не разрешает.

Пароли, ключи API и учётные данные Auth в бизнес-копию не входят. Проверка не разворачивает полноценный Auth, службу Storage и весь Supabase. Исходные файлы, карта ключей и доказательства остаются локально; в публичный GitHub их не публикуют. Таблицы читаются защищёнными блоками без общего ограничения 48 МиБ; строки сверяются частями в устойчивом порядке их ключей. Неполнота входа или несовпадение байтов дают явный отказ, а не успешную проверку.

## При продолжении разработки

Сначала читать AGENTS.md, HANDOFF_CURRENT_RU.md и текущую матрицу R01–R12. Действующая программа и исходная папка Кирьят-Гата не являются временными тестовыми каталогами. Старые пользовательские изменения, историю и применённые миграции не сбрасывать. Номер фактически применённой миграции корреспонденции:20261031083727_project_correspondence; файл исходного SQL:20261031120000_project_correspondence.sql. Повторно применять его к нынешней базе не требуется.

Технические проверки не заменяют приёмку реального результата. Текущий согласованный компьютерный охват и явные ограничения чтения/сенсорного управления/стандартов указаны в R01_R12_DELIVERY_RU.md. Будущие расширения не включены в итог только из-за успешной сборки.
