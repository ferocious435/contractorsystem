# Уроки проекта и известные проблемы (Lessons Learned)

## 1. Проблема с JS-PDF и отрисовкой иврита (RTL)
Библиотека `jspdf` и её плагины (например, `autotable`) **не поддерживают** рендеринг алфавита RTL (иврит) "из коробки". 
- Без пользовательских шрифтов текст либо превращается в "кракозябры", либо исчезает.
- Даже если инжектировать .ttf шрифт через Virtual File System (VFS), библиотека не выполняет BIDI-форминг: слова рендерятся задом наперёд.
- **Временный обходной путь (Fallback):** Использовался `window.print()` для печати HTML-документа как PDF, так как браузеры отлично поддерживают BIDI.
- **Долгосрочное решение:** Перевернуть слова (через `.split(' ').reverse().join(' ')`) перед отправкой в jspdf, либо вынести PDF-генерацию на бэкенд с помощью headless browser (Puppeteer/Playwright) или React-pdf.

## 2. Экспорт CSV на Windows и Иврит
Если вы генерируете CSV на стороне сервера и загружаете его, файлы с ивритом часто "ломаются" в MS Excel, так как он не понимает UTF-8 без специального маркера.
- **Решение:** Всегда прикрепляйте `BOM` (Byte Order Mark) в начале CSV строки: `\uFEFF`. Это заставляет Excel открывать файл правильно.

## 3. Конфликт Портов Next.js
При использовании параллельных процессов (например, React + Express Worker) порты `3000` и `3001` могут застревать в процессах Node.
- Из-за этого Next.js может перепрыгивать порты (3001 -> 3002).
- Всегда используйте команду `kill-port` (или аналогичный скрипт) при перезапуске сервера (он есть в `package.json` как `clean`).

## 4. Gemini JSON Mode
Смета (BOQ) и чертежи содержат сложную израильскую терминологию. Модель `gemini-3.5-flash` может иногда вернуть JSON с лишним текстом вокруг объекта. Проверка структуры должна использовать JSON mode и безопасное извлечение JSON-объекта, а не терять результат анализа.
