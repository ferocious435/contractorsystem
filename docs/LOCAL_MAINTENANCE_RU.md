# Обслуживание ContractorSystem

Сборка и упаковка проверяют, хватит ли места для очередной операции, и подают её в общий реестр. Обычный запуск, установка и возврат запускают обслуживание после подтверждения доступности программы. Результат каждого запуска сохраняется в служебном состоянии локальной установки.

## Что сохраняется

- Текущий рабочий выпуск, два предыдущих принятых выпуска, действующие кандидаты и файлы, которыми пользуется живой процесс.
- Исходники, уникальные журналы и доказательства, рабочие деревья, несохранённые правки, данные программы и закреплённые зависимости.
- Две последние неудачные сборки каждой задачи в течение семи дней. Открытая причина сбоя или закрепление продлевают защиту.
- Архивы с проверенным содержимым и указателем на исходную запись. Перед удалением старого выпуска или временной сборки программа сверяет полные контрольные суммы. Воспроизводимый кэш можно исключить из архива только при подтверждённом способе восстановления.

Целевой объём сборок — 4 ГиБ, старых незакреплённых выпусков — 6 ГиБ. Предупреждение начинается ниже 20 ГиБ. Перед большой записью программа проверяет, что после неё останется не меньше 12 ГиБ с учётом других операций. Причина превышения из-за защищённых материалов отображается в результате проверки.

## Порядок работы

Перед тяжёлой проверкой зарегистрируйте активную задачу с её рабочей папкой, кандидатом и закреплёнными файлами. Используйте один и тот же ID до завершения работы. Для обычной сборки Windows и помощников R05 и консультанта действует общий `local-system-build.mjs`. Изменившиеся входные файлы требуют новой проверки TypeScript перед сборкой.

```powershell
npm run local:maintenance
npm run local:context
npm run local:maintenance -- task --input task.json
npm run local:maintenance -- plan --output cleanup-plan.json
npm run local:maintenance -- apply --plan cleanup-plan.json
```

Первая команда показывает состояние. `local:maintain` — то же имя команды для обслуживания по событию, например `npm run local:maintain -- run --event start --task <id>`. `local:context` сверяет рабочую папку, ветку, опубликованный коммит, текущий выпуск, зарегистрированных кандидатов и ссылки. При расхождении или неизвестном результате команда возвращает код 1. Проверка контекста работает без блокировки обслуживания и сама не записывает данные.

План указывает точные пути и причины. Применение перечитывает защиты и контрольные суммы. При изменении пути, данных или владельца операции объект остаётся на месте. Для законченного кандидата используйте `close-candidate` с его `--task`, `--release`, `--result`, `--source` и `--dist` по исходной попытке. Для сборки используйте `close-build` с её `--task`, `--source` и `--result`. Состояние завершённой задачи сохраняется в том же реестре. Для Windows запуск сборки напрямую в папку с отметкой времени минует эти проверки. Запускайте `local-system-build.mjs`.

Файлы состояния, архивы и указатели лежат в локальной папке установки. Для Windows это `ContractorSystem/maintenance-state` внутри фактического локального хранилища приложения. Ошибка, неизвестный статус и предварительный список не подтверждают очистку. Перед отчётом пользователю отдельно сверяйте результат применения и изменение свободного места на диске.

## Восстановление архивных доказательств

Для отсутствующей локальной ссылки `local:context` ищет её в `maintenance-state/evidence-index/`. Запись указывает проверенный ZIP, исходный путь и расположение файла в архиве. Для ручного восстановления сначала сверьте архив с контрольной суммой записи. Извлеките его в новую отдельную папку через `extractVerifiedArchive` из `scripts/maintenance/archive.mjs` и сверьте нужный файл. Сохраните исходный архив и соседнее описание. Секции `artifact/`, `source/` и `evidence/` обозначены в записи индекса. Не разворачивайте архив поверх работающего выпуска или рабочей папки.

Перед заменой [текущей записи](HANDOFF_CURRENT_RU.md) перечитайте её, вычислите SHA256 и вызовите `archiveHandoff` из `scripts/maintenance/context.mjs` с этим SHA256 и локальным `docs/history/`. Функция сохраняет точные байты в новом файле. Перед записью заново проверьте сумму оригинала под исключительным доступом. При изменении перечитайте запись и объедините нужные изменения. История HANDOFF исключена из обычного добавления в Git.

## Копии данных

Обычный запуск проверяет изменение данных раз за местный день. Полная копия нужна при изменении данных и перед техническим изменением или переносом схемы. Совпавшие данные можно сослать на уже проверенную копию с сохранением причины и времени.

Новые обычные копии хранятся по правилу семи дневных, четырёх недельных и шести месячных точек. Совпавшая точка считается один раз. Последняя успешно восстановленная копия, закрепления и уникальные старые копии защищены. Для удаления устаревших копий нужны свежая завершённая копия и подтверждённое восстановление той же схемы и формата. Ошибка копирования или восстановления оставляет неисправную попытку для проверки и защищает прежние данные.

Команды резервного копирования и восстановления приведены в [инструкции запуска](LOCAL_OPERATION_RU.md). Изолированное восстановление проверяет бизнес-данные, исходные байты файлов и предусмотренные проверки прав. Его подтверждение хранится отдельно от состояния текущего выпуска.

## Границы

Обслуживание ограничено зарегистрированными рабочими папками и локальным хранилищем ContractorSystem. Рабочий архив, OneDrive, корзина, секреты, настройки доступа, история и модели Codex исключены. Статус проекта и следующий шаг ведутся отдельно в [текущей записи](HANDOFF_CURRENT_RU.md). Частные доказательства, документы, резервные копии и сборки сохраняются вне публикации исходников.
