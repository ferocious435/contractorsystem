# Проверяемый разбор изменения работ — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** В существующем финансовом потоке ContractorSystem показать воспроизводимый разбор MTM по связанным источникам, с отдельным проектированием и проверкой сопоставимости, без изменения финансовых строк.

**Architecture:** Общий пакет источников связывает текущий вопрос с документами проекта и исходными позициями. Существующие читатель и локальный адаптер формируют предварительные факты с точными цитатами; код проверяет их, числа и допустимость сравнения. Дополнительный режим существующего API и панель очереди показывают результат; неподтверждённое остаётся явно на проверке.

**Tech Stack:** Текущие TypeScript/Next.js/React, Supabase, установленный читатель и локальный адаптер, node:test. Новых зависимостей нет.

**Spec:** `docs/superpowers/specs/2026-10-26-mtm-system-review-design.md`.

## Global Constraints

- Одобрение проекта и выполнение получены; исполнитель один в текущем чате. Отдельный `project-manager` не установлен; объём и приоритеты ведёт `product-manager`, выполнение — `superpowers:executing-plans`.
- Выбор модели и режима не меняется; дополнительные AI-клиенты, исполнители, внешний обход и общая повторная обработка запрещены.
- Оригиналы доступны только для чтения. Финансовые строки, бюджет, решения владельца и архив не переписываются. Результаты модельного разбора сохраняются в отдельном локальном кэше; исходная карточка не меняется.
- Чтение обновляется только для заранее зафиксированного набора источников вопроса, с сохранением старых значений и исходных хешей. Документ со знакомыми ошибками OCR не распознаётся заново без изменения источника/явного повтора.
- Ограничение финансового вывода не обходить ради готового результата. Черновик и неизвестная редакция не становятся действующим указанием по имени или поздней дате.
- Синяя книга и 3210 — действующая основа с договорными исключениями; стандарты остаются отложенными.
- Остальная незавершённая ценовая доработка сохраняется и не устанавливается вместе с новым принятым режимом. Прежняя рабочая `.next` сохраняется до успешной проверки кандидата.

## Review Focus

1. Исходная позиция не содержит имени новой технологии: поиск через отсылки/описание, тест Task 1.
2. Совпадение общего слова и документ другого предмета: кандидат не становится обязательным основанием, тесты Tasks 1–2.
3. Чёткий текст рядом с непроверенной картинкой: факты остаются предварительными, автоматическая цена закрыта, Tasks 1–2.
4. Разные объёмы либо состав и отдельное проектирование: разность итогов не объявляется доплатой, Task 2.
5. Повтор проверки, конкурентное обновление исходника и старый принятый расчёт: кэш не скрывает изменения, финансовые данные не меняются, Tasks 2–3.

## Task 2: Факты с цитатами, сравнение и локальный кэш

**Files:** создать `src/utils/work-change-review.ts`, `src/utils/work-change-review-server.ts`, `scripts/verify-work-change-review.mjs`, `scripts/verify-work-change-service.mjs`; изменить только дополнительный режим `src/app/api/pricing/evaluate-ai/route.ts`.

**Interfaces:** `WorkChangeFact` содержит id/sourceId/kind/evidence/quantity/unit/amountExclVat/observedAmount/confirmed/issues. Виды различают BASELINE_WORK, PROPOSED_WORK, BASELINE_TOTAL, PROPOSAL_TOTAL, DESIGN_FEE, CLAIM_TOTAL, AGREEMENT, OPEN_QUESTION. `validateWorkChangeReview(packet,drafts): WorkChangeReview` проверяет цитаты через `findEvidenceAnchor`, суммы/количества через исходный текст и чтение; возвращает sources/facts/comparisons/limitations/requiresReview. `reviewWorkChangeCase({supabase,projectId,findingId,refreshReading}): Promise<{review:WorkChangeReview;cached:boolean;updatedDocumentIds:string[]}>` выполняет последовательные запросы существующего локального адаптера и сохраняет отдельный локальный продуктовый кэш. API принимает `reviewCaseOnly:true`; старый путь не меняется. Уточнение при реализации: у contradictions нет updated_at; замена большого evidence_data небезопасна для конкурентных правок владельца. Поэтому `work-change-cache-server.ts` хранит кэш атомарно в игнорируемой `data/work-change-cache/`, без изменения карточки и без новой схемы БД. Это сужает мутации относительно первоначального проекта.

## Самопроверка и исполнение

Уточнения по результатам реального прогона: короткие связанные письма читаются с приложениями целиком; интервалы сметных позиций включают промежуточные строки и полное описание. Явные табличные столбцы проверяются программно отдельно от модельной классификации. Количество, цена единицы и сумма строки не подменяют друг друга; одинаковый код в разных местах требует проверки раздела/строения. Выделенное предложение проектировщика сохраняет явно обозначенный гонорар, даже если локальная классификация пропустила его. Суммы разных документов автоматически не складываются. Это проверки исходных полей внутри согласованного механизма; выбор модели и финансовые записи не меняются.

Сбор источников/чтение — Task 1, смысл/цитаты/числа/раздельные расходы — Task 2, продуктовый результат/сохранность/установка — Task 3. Общий интерфейс packet используется всеми тремя задачами. Обнаруженный побочный эффект прежнего extract-text (синхронизация бюджета) исключён из нового дочитывания. Дополнительные AI-исполнители запрещены: итоговая проверка кода самостоятельная по шаблону review, что явно фиксируется. Одобрение проекта и поручение выполнить его получены в текущем чате; новый запрос того же одобрения не требуется.

## Фактический результат 26–27 октября 2026 года

Статус — **частично**. В рабочий выпуск включён безопасный просмотр связанных документов, табличных столбцов, отдельного проектирования и конкретных ограничений. 53 программные проверки нового режима, 171 профильная регрессия, финансовые инварианты, TypeScript, ESLint и production-сборка прошли. Существующая проверка локального радара прошла 17 случаев; это не оценка точности модели на независимых проектах.

Реальный продуктовый прогон нашёл связанные источники и исходные позиции, правильно выделил доступные табличные данные и отдельный гонорар. Но локальная классификация путала исходную работу с предложенной. Содержательная приёмка этой части **не пройдена**. Непроверенные фрагменты показываются отдельно; финансовое сравнение по ним запрещено, окончательная доплата не рассчитана. Ожидания проверки не заменены ответами модели.

Незавершённый шаг — надёжное сопоставление состава заменяемых и предложенных работ. Критерий завершения проекта сохранён; установка защищённого просмотра не означает закрытия MTM или завершения всего ценового этапа.

Визуальная приёмка обнаружила отдельный дефект упаковки: сборка из игнорируемой папки не создавала основные CSS-классы. После возврата прежнего выпуска сборка перенесена во временную неигнорируемую папку, источники стилей ограничены src, в архив включены PostCSS/ESLint-конфигурации. Добавлена проверка готового CSS для расположения диалога, сеток и прокрутки; RED/GREEN получены на настоящем production-результате. Настройки опираются на [правила обнаружения классов Tailwind](https://tailwindcss.com/docs/detecting-classes-in-source-files); поведение игнорируемой папки отдельно воспроизведено локально. Исправленный экран проверен снимком до повторной установки.
