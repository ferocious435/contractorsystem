# PRD: Техническая Архитектура MVP
**Статус:** Согласовано (Бизнес и Технология)

## 1. Стек технологий
- **Фронтенд:** Next.js + React (RTL, Dark Mode).
- **Бэкенд:** Next.js API Routes (встроенный в приложение бэкенд).
- **База данных:** Supabase PostgreSQL (Используем бесплатный тариф BaaS для масштабируемости, хранения юзеров и синхронизации).
- **Хранилище файлов:** Supabase Storage.
- **ИИ-Провайдер:** Gemini 3.1 Pro High (или последние версии подписки пользователя) — полная поддержка текстовых потоков (многомиллионный контекст), аудио и видео.

## 2. Развертывание (DevOps)
- **Локальная разработка (Local Dev):** Локальная машина (Windows + Node.js), доступ по `http://localhost:3000`.
- **Продакшн (Live):** Бесплатный серверный хостинг `Vercel` (Hobby Tier), связанный с облачным `Supabase`.

## 3. Пайплайн загрузки и парсинга (Гибридный Локальной Подход)
**Главное правило:** Никаких сторонних платных API для чтения документов, кроме подписки на саму LLM. Локальная детерминированная обработка до ИИ.

- **Загрузка:** Классический UI-компонент "Загрузить файл(ы)" в браузере.
- **Асинхронные Очереди (Background Processing):** Во избежание зависаний (Timeout / 504 Error) при массовой загрузке файлов (50+ документов), извлечение данных происходит в асинхронном фоновом режиме. Файлы обрабатываются строго по одному (בטור). UI обновляется в реальном времени (от "В обработке" до "Готово").
- **Текстовые PDF и Excel (Сметы):** Парсятся *строго локально* скриптом на сервере. Извлекаются "чистые" сырые таблицы и текст в жесткий JSON.
- **Сканы, Чертежи, Видео и Голос:** Передаются напрямую в модуль Vision/Аудио (Gemini 3.1) для мультимодального пространственного чтения.
- **Этап ИИ (Анализ и Сравнение):** "Сырой" и 100% точный JSON-массив данных кормится в LLM. ИИ не пытается "угадать" таблицу, он лишь применяет строительную логику к готовой таблице.
