# PRD: תמחור וחריגים (Бюджет и Доп. Работы)
**Статус:** Согласовано (Бизнес-логика ИИ-Сметчика)

## 1. Цель Экрана
Конвертация найденных ошибок в юридические финансовые требования (Счета/V.O.). Место, где детально просчитывается прибыль подрядчика на основе реальных контрактов и прайс-листов. Включает карточки из Радара и новые, введенные вручную виды работ.

## 2. Функциональные требования (UX/UI)
- **Очередь Ожидания (Pending Queue - תור תמחור):**
  Экран начинается **не** с пустого места. Сверху (или слева) находится "Очередь", куда падают все 100% карточек, переданные с экрана "בקרת סתירות" (через кнопку `העבר לתמחור`). Они ждут привязки к ценам.
- **1:1 Traceability (Идентичность карточек):** 
  Карточки в Очереди сохраняют визуальный стиль Радара и все сноски/пруфы `[1]`.
- **The Ledger (Матрица Выполнения):**
  Основная таблица (Смета по Контракту vs Фактические отклонения). Оцененные карточки падают сюда (становясь строкой бюджета).

## 3. Движок Оценки (AI Estimator & Priority Hierarchy)
Функционал оценки применяется ко ВСЕМ элементам: и к карточкам из Очереди Радара, и к новым ручным вводам (через текстовое поле "יעוץ חכם").

1. **Жесткая Иерархия Прайсов (The Priority Engine):**
   При старте оценки (ручной или из Очереди), система *всегда* визуализирует порядок поиска цены: `1. חוזה (BOQ) -> 2. מחירון דקל -> 3. מחירון קבלן`. Система пишет прямо на карточке: *"Считаю по Смете..."*. 
   Пользователь **в любой момент** может нажать на выпадающий список (Dropdown) и принудительно изменить приоритет для конкретной позиции (например, заставить считать по Декель вместо Контракта).
2. **Многовариантный Опрос (Американский Тест):** Если ИИ нашел совпадения в приоритетном прайсе (например, 5 видов "брусчатки" в Контракте), он задает уточняющие вопросы из текста сметы *(Толщина? [6см] [8см])* для точного выбора статьи.
3. **Прямое совпадение:** ИИ нашел 100% точную статью. Цена присваивается автоматически (с возможностью ручного оверрайда).
4. **Zero-Match (Сборка с нуля / ניתוח מחיר):** 
   Работы нет ни в одном из прайс-листов иерархии. ИИ создает "ניתוח מחיר" (Часы/Материалы/Техника). Система предзаполняет форму своими оценками, но **пользователь имеет полный ручной контроль (Manual Edit)** над каждой цифрой, часом и процентом накидки (רווח קבלני) перед сохранением.

*Важное правило НДС (מע"מ):* Все расчеты ИИ, прайс-листы и "ניתוח מחיר" всегда оперируют суммами **БЕЗ НДС** (לפני מע"מ). НДС рассчитывается и показывается отдельно только в итоговых колонках матрицы.

## 4. Архитектура обработки данных (Pipeline)
- **Linkage (Связь с базой):** Каждая "Хриг"-карточка жестко привязана к выбранному источнику (ID Сметы или ID внешнего Прайс-листа).
- **מחולל מכתבי חריגים (AI V.O. Composer):**
  Главный генератор бумаг. Подрядчик выделяет галочками карточки (חריגים) и жмет "Сгенерировать письмо". ИИ собирает официальный PDF-документ (מכתב דרישה).
  *Финансовый блок PDF:* Сухой юридический текст, точные расценки **до НДС**, отдельная строка с **суммой НДС**, и финальная сумма **включая НДС** (סה"כ כולל מע"מ). Доказательства из Радара прикладываются в конце.
